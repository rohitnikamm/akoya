# Mac Pill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show dictation on the Mac in a floating pill like the Windows one, as the default, with the menu bar waveform kept as an option.

**Architecture:** Pure logic in `AkoyaCore` (dot opacities, pop-in frames, placement, what the pill shows and for how long), each ported from or mirroring `windows/src/Akoya.Core/Ui/` with Swift Testing tests. `AppCoordinator` gains a pill mode that reports each dictation's outcome instead of flashing the menu bar. A borderless non-activating `NSPanel` hosts a SwiftUI pill view; `AppDelegate` wires it up.

**Tech Stack:** Swift 6, SwiftUI + AppKit, Swift Testing (`swift test`), macOS 14+, Apple Silicon.

**Spec:** `docs/superpowers/specs/2026-10-22-mac-pill-design.md` (mockup: `docs/design/mac-pill-mockup.html`)

## Global Constraints

- Pill: 34 pt tall, radius 17, padding 0 15, gap 10; glass `#0E1222`→`#090D1E`; rim glow `#2F6BFF` (alerts `#EF4444`); dots `#DBE6FF`; red waveform `#FF6B6B`; amber scanner `#FBBF24`; timer white 50 % 11.5 pt tabular; label white 90 % 13.5 pt (Outfit, `AkoyaFonts.outfit`).
- Waveform: 23 columns × 4 rows of 3 pt dots, 2 pt gaps. Scanner period 1.4 s.
- Durations: "Pasted" 0.9 s; alerts 1.6 s; pop-in 0.42 s; hide 0.28 s (sink 10 pt, scale 0.94, cubic-bezier(0.2, 0.8, 0.2, 1)).
- Placement: 20 pt above the Dock top (bottom Dock, also when auto-hidden and on screens without the Dock); 20 pt above the visible frame's bottom when the Dock is left or right.
- Copy, exactly: "Pasted", "Getting the speech model ready…", "Speech model failed", "Turn on your mic in System Settings", "Microphone not detected"; dropdown "Dictation indicator", "Show while dictating", "Pill", "Menu bar", "Hide menu bar icon when idle".
- Default indicator: Pill, for new installs and upgrades (key `akoya.indicator`, values `"pill"` / `"menuBar"`).
- Menu bar mode must behave exactly as today (all existing `AppCoordinatorTests` and `WaveformLayoutTests` keep passing unchanged).
- Commits: no Claude co-author trailer, no "Generated with Claude Code" (CLAUDE.md).
- Every visual result is screenshotted and looked at before it is shown to Rohit (CLAUDE.md).

## Review Focus

1. **Focus is never stolen:** while the pill shows, the app being typed into keeps key focus and the paste lands there. Task 7 (panel flags) + manual check in Task 9.
2. **A press during "Pasted" or an alert starts a new dictation** in pill mode (menu bar mode still ignores presses during its 0.6 s flash). Tests in Task 5 and Task 6.
3. **Switching Pill ↔ Menu bar mid-dictation** applies at the next dictation; the current one finishes on the indicator it started with. Test in Task 6.
4. **Practice (onboarding Try it) never shows the pill**, in either mode. Test in Task 6.
5. **Multiple displays and full-screen Spaces:** the pill appears on the screen with the focused window, at the same height on every screen. Placement tests in Task 4; manual check in Task 9.
